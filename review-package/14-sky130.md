# 14 — sky130 synthesis, STA and post-P&R (TASK2 Phase 4)

Run 2026-09-04. Everything here is produced by scripts committed under
`flow/` and is reproducible from a clean checkout plus the tools in
`10-toolchain.md`. Target: `ibex_top` in the port's configuration on
both lanes (RV32IMC, RV32MFast, 2-stage, ICache=1 with 2 ways × 256
lines, PMP=1 with 4 regions, FF register file, no branch predictor,
RVFI off), identical parameter overrides, constraints and tool
versions.

## 4.1 Source lists

`flow/make_filelists.py` derives both lists from the fusesoc-resolved
Verilator command file the test harness produces, mapping every staged
copy back to its `$IBEX_ROOT` original by basename + content hash, so
the lists reference `${IBEX_ROOT}` (upstream lowRISC/ibex `eede2fb`) and
`${REPO_ROOT}/build/` (the Arch lane's generated SV) rather than a temp
directory:

| List | Files | Content |
|---|---|---|
| `flow/ibex_top_sv.f` | 128 | upstream Ibex RTL + vendored `prim_*` (generic RAM models `prim_generic_ram_1p`, so memories are inferred, not black-boxed) |
| `flow/ibex_top_arch.f` | 133 | same minus the 18 ported files, plus the 23 generated `build/*.sv` (package first) |

Both lists carry the same `+incdir+` set and the same defines
(`SYNTHESIS`, `RV32M`, `RV32B`, `RV32ZC`, `RegFile`). Three kinds of file
are deliberately excluded from both, none of which is instantiated
under `ibex_top`: the simulation tracer / tracing wrapper
(`ibex_tracer.sv`, `ibex_tracer_pkg.sv`, `ibex_top_tracing.sv`), and
three pad/IO primitives the fusesoc lint tree drags in
(`prim_usb_diff_rx.sv`, whose drive-strength `assign (weak0, pull1)` Yosys
cannot parse, `prim_pad_wrapper.sv`, `prim_pad_attr.sv`). `-DRVFI=1`
from the simulation harness is dropped: the ARCH port ties every RVFI
output to zero (`specs/ibex_top/spec.md` note N-1) whereas upstream
would add real trace-tracking logic under `ifdef RVFI`, so RVFI-off is
the like-for-like comparison.

sv2v 0.0.13 (`--define=SYNTHESIS --define=YOSYS` plus the list's

| Lane | Result | Output |
|---|---|---|
| SV | ok, no errors | `flow/out/sv/ibex_top.v` (17,373 lines) |
| Arch | ok, no errors | `flow/out/arch/ibex_top.v` (16,382 lines) |

The Arch lane converts only with the final compiler pin (arch-com main
`89ec0522`, equivalent to release `v0.72.0`): release v0.71.0's emitter indexes unnamed expressions

## 4.3 Logic synthesis + STA — `flow/sky130_synth.sh`

Recipe, identical per lane: `read_liberty -lib` (sky130_fd_sc_hd, tt
25 °C 1.80 V), `read_verilog -sv`, `hierarchy -check -top ibex_top
-chparam …` (the port's configuration; `DummyInstructions` and
`RegFileECC` are left at their common default 0 because overriding them
trips a Yosys `defparam` error on the upstream top), `proc`, per-module
`memory -nomap` **before** `flatten` (the ordering the May notes found
necessary so parallel RAM write ports are not dead-code-eliminated),
`memory_map`, `synth`, `dfflibmap`, a techmap for the single generic
latch (`flow/sky130_latch_map.v` → `dlxtn_1`; the latch is upstream's
generic clock-gate enable latch, present on both lanes), `abc
-liberty`, `setundef -zero` + `hilomap -singleton` (undefined bits to 0,
constant drivers to one `conb_1` HI and one LO tie cell — added after the
first P&R attempt, see §4.4; +2 cells / +7.5 µm² per lane, STA
unchanged), `stat -liberty`, `write_verilog`. Then OpenSTA 3.1.0 with one
clock, `clk_i` at **10 ns**, zero I/O delays, reading a copy of the
netlist with the (timing-irrelevant) `signed` keyword stripped from
wire declarations, which OpenSTA's reader rejects. Yosys 0.67+post.

condition asked for in the task — zero black-boxed cells — holds on
both lanes.

## 4.4 Post-P&R — OpenROAD regression flow on sky130hd (`flow/openroad/`)

OpenROAD-flow-scripts is not installed on this host (`10-toolchain.md`);
the prepared ORFS configs under `flow/orfs/` are kept for reference but
were not run. Instead both lanes go through **OpenROAD's own regression
flow** (`~/github/OpenROAD/test/flow.tcl`, OpenROAD 26Q2-1287): floorplan
→ tap cells → power grid → global placement (routability-driven,
4-site padding) → `repair_design` → detailed placement → clock-tree
synthesis → `repair_timing` → global route → detailed route → antenna
repair → fillers → parasitic extraction (RCX) → final STA. Platform files
and knobs are OpenROAD's `test/sky130hd/sky130hd.vars` (the same the
project's own `ibex_sky130hd` regression uses), with three values set
identically on both lanes in `flow/openroad/lane.tcl`: `slew_margin 30`,
`cap_margin 25`, `global_place_density 0.5`. Constraint:
`flow/openroad/constraint.sdc` — one clock `clk_i` at **10 ns** (the same
clock as §4.3) and 2 ns (20 % of the period) input and output delays on
every non-clock port, as OpenROAD's own `ibex_sky130hd` regression uses.

**Die sizing rule (`flow/openroad/run.sh`).** Square die whose core
holds the lane's synthesised cell area at **25 %** utilisation plus a
10 µm margin: SV 2,656 × 2,656 µm, Arch 2,774 × 2,774 µm. A first attempt
at 50 % (SV 1,884 µm, Arch 1,968 µm) failed: the regression flow pads
every cell by 4 sites per side in global placement and `repair_design`
added 20,317 buffers, so the padded cell area (3.21 M µm²) filled 93 % of
the 3.47 M µm² core, the placer raised its target density to 0.93, and
detailed placement could not legalise 5,977 of the 24-site-wide
`edfxtp_1` enable flops (`DPL-0036`, 31 min in; log kept at
`<scratch>/pnr-attempt1/sv_openroad.log`). A second attempt at 25 %
placed and built clock trees on both lanes but stopped at detailed
routing: the synthesis netlist connected constants directly
(`assign x = 1'h0`, plus two `2'hx` bits), which OpenROAD's reader turns
into `zero_`/`one_` nets of signal type POWER that TritonRoute refuses
(`DRT-0305`; `<scratch>/pnr-attempt2/`). The synthesis script now maps
constants to `conb_1` tie cells (`setundef -zero; hilomap -singleton`,
as OpenROAD-flow-scripts does), which the flow's `repair_tie_fanout`
then splits per load; §4.3 was re-run and its numbers above are from
that netlist. At 25 % the padded minimum
feasible density is 0.44 (SV) / 0.47 (Arch) under the 0.5 target. The
netlist fed to OpenROAD is the `signed`-stripped copy used for STA in
§4.3 (OpenROAD's Verilog reader rejects `wire signed` too; identical to
the raw netlist on the SV lane, one declaration differs on the Arch
lane).

Reading the numbers:

- **Area.** Post-P&R the gap widens from 1.059× (synthesis) to 1.079×:
  the Arch lane needs more combinational area (+79 k µm²), and its
  timing-repair buffering is larger in area though fewer in count
  (bigger buffers on longer nets: global-route wirelength is 1.17×).
  The sequential population is the same +931 flops as at synthesis.
- **Timing.** Neither lane closes 10 ns. The worst setup path is
  register-to-register in the `core_clock` group on both lanes and ends
  at an enable flop (`edfxtp_1`) of the icache RAM arrays after a long
  buffer tree (the arrays' 11 k-fanout write/enable nets, buffered by
  `repair_design`): on the SV lane the path is two `dfrtp_1` stages,
  ~20 gates of control logic and ~44 buffers; on the Arch lane it runs
  through an adder carry chain and ~41 larger buffers before the same
  kind of endpoint (101 stages on 0.72.1). Traced to named nets in the
  routed netlists, the SV path starts at the `mie` CSR and the Arch path
  at the flop feeding `register_file_i.raddr_a_i`: both are the
  fetch/branch loop into the icache enables, not the multiplier/divider. Instance names
  in the reports are Yosys-anonymised (`_NNNNNN_`), so the path is
  characterised by its cell mix, not by RTL signal. The hold
  violations are on input-port paths (worst: SV `data_rdata_i[15]`, Arch `fetch_enable_i[0]`) under the 2 ns input delay, and
  `repair_timing` reported it could not fix all violations on either
  lane (`RSZ-0062`).

  to appear here is withdrawn as not comparable across a netlist
  restructuring; see the Table 10 note. Raw `*_final_power.rpt`
  files are kept as evidence for that note, not as a result.
- **What this says about the port.** On this flow the ARCH-generated
  core is 8 % larger and 23 % slower after place-and-route, versus 6 %
  larger at synthesis and 15 % slower on the ECP5 FPGA
  (`15-ecp5.md`). The flop-based RAM arrays dominate area on both lanes
  and their enable-net fanout sets the critical path on both; the Arch
  lane's extra logic sits in front of that fanout.

## 4.6 Synthesis re-run on arch 0.72.1 — a 3 % Arch-lane area change from three declaration initializers

arch-com 0.72.1 (PR #1001, closes #995) changes exactly one generated file of the
port, `ibex_multdiv_fast.sv`: the thread's `_t0_state`, `_t0_cnt` and `_t0_loop_cnt_0`
lose their `= 0` declaration initializers and the two counters move into the
thread's reset branch (18 diff lines; every other file is byte-identical). Same
flow, same scripts, same tools; previous Arch reports kept as
`reports/arch_sky130_v0720_*`.

| Arch lane, flattened synthesis | 0.72.0 (§4.3) | **0.72.1** | delta |
|---|---|---|---|
| Cells | 126,389 | **114,307** | −12,082 (−9.6 %) |
| Chip area (µm²) | 1,896,047 | **1,838,368** | −57,679 (**−3.0 %**) |
| Flip-flops | 47,650 | 47,660 | +10 (one-hot recode of the thread FSM) |
| Ratio to the SV lane (1,736,611 µm²) | 1.092× | **1.059×** | |
| Synthesis-netlist STA WNS / TNS (still not usable, §4.3) | −26,490 / −32,066,592 ns | −656 / −5,840,706 ns | worst path now a reset-recovery check, no longer the RAM-enable fanout |

The cell mix moves wholesale (`nand3_1` 23,860 → 643, `a41oi_1` 4,683 → 18,
`a22oi_1` 9,203 → 23,362, `a21oi_1` 7,608 → 14,104); the −12k cells all drive
Yosys-anonymous nets, so they cannot be attributed by name. Three controlled
re-syntheses (`<scratch>/variant`, `<scratch>/nofsm`, `<scratch>/multdiv-cmp`) pin
the cause down:

- Yosys 0.72.0 log: "Not marking … `_t0_state` as FSM state register: Register has
  an initialization value"; on 0.72.1 it extracts and one-hot-recodes that FSM. But
  re-synthesising the 0.72.1 netlist with `synth -nofsm` still gives 114,420 cells /
  1,838,752 µm², so FSM extraction is not the cause.
- `ibex_multdiv_fast` synthesised **alone** is 6,991 cells / 48,142 µm² on 0.72.0 and
  7,333 / 50,206 on 0.72.1 (+4 %): the module itself does not shrink.
- The 0.72.0 multdiv file with **only the three `= 0` initializers deleted** (no other
  change) synthesises the whole flattened design to 114,622 cells / 1,839,842 µm².

So the entire drop is what Yosys does with the `init` attributes those three
initializers create on the flattened netlist (`Set init value: _t0_state = 4'0000`,
`_t0_loop_cnt_0 = 5'00000` in the 0.72.0 log): with them present, ABC's whole-design
mapping lands on a markedly worse structure for logic far from the multdiv (the
icache RAM-enable decode is where the `nand3`/`a41oi` population lived). Two
consequences for reading this package: (1) the Arch lane's synthesis area on 0.72.0
carried a ≈3 % penalty from a compiler artefact the SV lane never had (upstream Ibex
writes no declaration initializers); on the released 0.72.1 the synthesis gap is
1.059×, not 1.092×; (2) this flow's flattened ABC mapping is sensitive to netlist
details at the several-percent level, which bounds the precision of any single
synthesis-area comparison made with it.
